## The Problem

Automatic Weather Stations feed the data behind flood warnings, crop advisories, and flight plans — but sensors drift, fail, and go silent, and bad data can silently corrupt forecasts with nobody noticing until it's too late.

## What SkyGuard AI Does

Instead of a binary "anomaly / not anomaly" flag, SkyGuard AI produces a **0–100 Trust Score** for every reading and **diagnoses the root cause**:

- `HARDWARE_FAULT` — a failing physical sensor
- `SENSOR_DRIFT` — slow calibration drift
- `COMMS_LOSS` — a communications/power interruption
- `EXTREME_WEATHER` — a genuine event confirmed against neighboring stations
- `CALIBRATION_ERROR` — a multivariate configuration issue

Every flag comes with a plain-English explanation and a recommended action, generated by an ensemble of a statistical MAD/Z-score model, an Isolation Forest, and a spatial neighbor cross-check.

## Live Demo

A "⚡ Inject Live Fault" panel lets you pick a station, a parameter, and a fault type, and watch detection, root-cause classification, and explanation happen in real time — see [`docs/demo-script.md`](docs/demo-script.md).

## Quick Start

### Option A — Docker Compose (recommended)

```bash
git clone https://github.com/<your-username>/skyguard-ai.git
cd skyguard-ai
docker compose up --build
```

- Backend: http://localhost:8000/docs
- Frontend: http://localhost:5173

### Option B — Run locally

```bash
# Backend
cd backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000

# Frontend (separate terminal)
cd frontend
npm install
cp .env.example .env
npm run dev
```

## Tech Stack

- **Backend:** FastAPI, scikit-learn, NumPy, WebSockets
- **Frontend:** React 18, TypeScript, Vite, Recharts, Framer Motion
- **AI/ML:** Isolation Forest, MAD-based statistical detection, spatial neighbor cross-validation, rule-based root-cause classification (LSTM autoencoder + spatial GNN planned — see Roadmap)
